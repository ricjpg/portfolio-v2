# Propuesta de solución: arquitectura cloud para e-commerce

Esta propuesta presenta una arquitectura en Azure orientada a una plataforma de comercio electrónico empresarial. La solución está diseñada para soportar crecimiento escalable, mantener altos estándares de seguridad y garantizar disponibilidad continua para operaciones críticas.

## Objetivos principales

- Escalabilidad: la infraestructura debe crecer con la demanda del negocio
- Seguridad: aplicación de prácticas cloud-native y políticas de acceso robustas
- Disponibilidad: asegurar continuidad operativa para servicios críticos
- Observabilidad: facilitar el monitoreo, la trazabilidad y la resolución de incidentes

# Arquitectura propuesta

La solución se estructuró en tres capas principales que permiten separar responsabilidades y mejorar la mantenibilidad del sistema:

```text
Security & Identity  ->  Core Application  ->  Data & Analytics
```

![General Diagram](../../../public/images/general-diagram.png)

## Repositorio 1: seguridad e identidad

Este repositorio se enfoca en la capa de seguridad y la gestión de identidad. Su responsabilidad principal es proteger la infraestructura y controlar el acceso a los recursos mediante políticas centradas en autenticación, autorización y cumplimiento.

Incluye:

- Políticas de seguridad y acceso condicional
- Autenticación para usuarios y clientes
- Azure Key Vault para secretos y certificados
- Network Security Groups y reglas de firewall
- Configuración de dominios personalizados y SSL

## Repositorio 2: aplicación central

Este repositorio concentra la lógica de negocio y los servicios de la plataforma digital. Incluye los componentes principales para ofrecer la experiencia de compra, administración interna y servicios de operación.

Entre sus elementos destacan:

- Portal de front office
- Portal de back office
- API RESTful
- Azure Service Bus y Queue Storage
- Azure Functions
- Servicio de notificaciones
- Application Insights para monitoreo y observabilidad

![Core App Architecture](../../../public/images/core-app-arq.png)

## Repositorio 3: datos y analítica

Este repositorio agrupa todo el ecosistema de almacenamiento y análisis de datos. Está orientado a gestionar información transaccional, almacenamiento de archivos y preparación de datos para reporting y analítica avanzada.

Incluye:

- Azure Blob Storage para contenido multimedia
- Base de datos transaccional y de caché
- Pipelines ETL
- Synapse Analytics
- Power BI para reporting de negocio
- Data Factory
- Políticas de respaldo y recuperación

![Database Architecture](../../../public/images/database-arq.png)

# Justificación de la arquitectura

## Principio de responsabilidad única

Cada repositorio cumple una función específica y bien definida. Esta separación mejora la organización del código, facilita el mantenimiento y reduce el riesgo de cambios cruzados.

### Seguridad e identidad

Se centra exclusivamente en protección y acceso, dado que sus cambios suelen requerir revisiones más rigurosas y un mayor nivel de control debido a requisitos regulatorios y de auditoría.

### Aplicación central

Agrupa la lógica de negocio y los servicios funcionales. La convivencia de estos componentes es necesaria porque comparten despliegues, dependencias y pruebas de integración.

### Datos y analítica

Mantiene el ecosistema de almacenamiento y procesamiento de datos bajo una misma visión técnica, ya que estos elementos comparten políticas de retención, seguridad y acceso.

## Acoplamiento débil y cohesión alta

Se busca minimizar dependencias entre repositorios y aumentar la cohesión interna de cada capa. Este enfoque permite evolucionar cada dominio sin comprometer la estabilidad de los demás.

- Seguridad e identidad: alta cohesión por la relación directa entre políticas, certificación y acceso
- Aplicación central: acoplamiento funcional justificado entre frontend, backend y servicios de integración
- Datos y analítica: cohesión en la gestión de almacenamiento, ETL y reporting
